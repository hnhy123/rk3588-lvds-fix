# RK3588 LVDS 间歇闪屏修复（Really TVI2340R 直播机）

修复 RK3588 直播机 **整屏间歇性发灰/无图像、背光仍亮、日志毫无线索** 的闪屏问题。

改一行像素时钟就好，不需要换内核、不需要重刷镜像。

```
面板链路： VOP2 (VP3) → MIPI-DSI2 → LT9211 桥 (I2C 0x2d) → LVDS 1920x1080
原厂配置： 148.5625 MHz 像素时钟 / 1920x1080@60  → 链路锁定余量不足，周期性失锁
本补丁：   132 MHz / 垂直消隐加长            → 精确 50.0000 Hz，稳定不闪
```

## 症状

- 屏幕上**整屏一瞬间没图像**，看起来"发灰、发白但还亮着"，随后自己恢复
- 间歇出现，与 CPU/GPU 负载无关，静止不动也照闪
- `dmesg`、`journalctl` **一条相关错误都没有**
- 用手机相机拍屏幕**看不到** PWM 横条纹（说明不是背光频闪）

如果符合以上描述，基本就是本文这个问题。

## 适用环境

- Really TVI2340R / 同源 RK3588 直播机（设备树里有 `/panel-lvds/panel-timing`）
- Armbian `edge` 分支，实测内核 `7.3.5-edge-rockchip64`
- 面板 1920x1080，经 Lontium LT9211 从 DSI 转 LVDS

不适用：HDMI / eDP 输出、或面板直接用 RK3588 内置 LVDS 的机型。

## 快速使用

```bash
# 拷到机器上
chmod +x really-lvds-fix.sh

# 先看当前状态（不改动任何东西）
sudo ./really-lvds-fix.sh --check

# 打补丁并重启
sudo ./really-lvds-fix.sh --reboot
```

重启后 `--check` 应显示：

```
==> 状态: 50 档（132MHz，精确 50Hz）
==> 面板: connected  DPMS: On
==> 运行模式: "1920x1080": 50 132000 1920 2008 2052 2200 1080 1084 1089 1200
==> VOP 像素时钟 dclk_vop3: 132000000 Hz
```

## 两个档位

脚本内置两档，都在实机上验证过（不闪、显示正常）：

| | **50 档（默认）** | **48 档（备用）** |
|---|---|---|
| 参数 | `--profile 50` | `--profile 48` |
| `clock-frequency` | 132,000,000 | 123,750,000 |
| PLL 实际取到 | 132.0 MHz | 118.8 MHz（PLL 取不到 123.75，向下取整） |
| `vback-porch` | 111（原厂 36） | 36（原厂值） |
| htotal / vtotal | 2200 / 1200 | 2200 / 1125 |
| 刷新率 | **50.0000 Hz** | **48.0000 Hz** |
| 链路速率 | 较高 | 最低，最保守 |

选择建议：**先跑默认的 50 档**。如果那台机器仍然闪，说明它的面板余量更小，加 `--profile 48` 退到最低链路速率档。

```bash
sudo ./really-lvds-fix.sh --profile 48 --reboot
```

## 补丁到底改了什么

`/panel-lvds/panel-timing` 下的两个属性（50 档）：

```
clock-frequency   148562464  →  132000000
vback-porch              36  →  111
```

**水平时序一个字没动**（hfront 88 / hsync 44 / hback 148 保持原厂），这是有意为之——见下面的"死路"。

刷新率 = 像素时钟 ÷ (htotal × vtotal)，所以 `132000000 ÷ (2200 × 1200) = 50.0000`，是精确整数，不靠取整。

## 其它命令

```bash
sudo ./really-lvds-fix.sh --check              # 只看状态
sudo ./really-lvds-fix.sh --restore --reboot   # 回滚到原厂 60Hz
sudo ./really-lvds-fix.sh --hold               # 打补丁并 apt-mark hold，防升级覆盖
sudo ./really-lvds-fix.sh --dtb /path/x.dtb    # 手动指定 dtb
sudo ./really-lvds-fix.sh --force              # 当前值不认识时强制改
```

脚本的安全设计：

| 情况 | 行为 |
|---|---|
| dtb 里没有该节点 | 拒绝执行（换型号不误伤） |
| 已是目标档位 | 提示无需操作，退出 0（幂等） |
| 当前值既非原厂也非已知档位 | 停下，需 `--force` |
| 每次改动 | 自动备份 `*.dtb.bak.<时间戳>` |
| 写入后 | 读回校验，不一致立即报错 |

用 `fdtput` **原地修改**，不重编译整个 dtb，文件大小不变、其余节点不受影响。

## 为什么日志里什么都没有

这是这个问题最反直觉的地方，也是排查时最容易卡住的原因。三个环节同时失明：

1. **DSI2 驱动没有注册中断**。设备树里 `dsi@fde30000` 声明了中断（GIC SPI 168），但 `/proc/interrupts` 里根本没有这一条——所以链路出问题时内核收不到任何事件。
2. **LT9211 是"哑桥"**。驱动只在上电时写一遍寄存器，之后不轮询状态。它失锁、重锁，内核完全不知道。
3. **面板供电是纯 GPIO 开关**（`gpio-14 / regulator-lvds-pwr-en`）。只要这个 GPIO 保持着，内核就认为面板一切正常。

所以"闪屏 + 零日志"不代表软件没问题，而是**软件根本没有观测点**。

## 排查过程（可复现）

确认是这个原因、而不是背光/合成器/负载问题，靠的是下面这些实测。详见 [docs/diagnosis.md](docs/diagnosis.md)。

- `actual_brightness` 全程不变、DPMS 全程 `On` → 不是调光、不是熄屏
- 打开 `drm.debug=0x04` 后，闪屏期间 **modeset = 0 次** → 不是合成器重配
- 20 Hz 盯 `gpio-14`，**0 次跌落** → 面板供电使能没掉
- 20 Hz 读 LT9211 寄存器，**0 次 NAK** → 桥芯片没复位、没掉线
- 手机拍屏无横纹 → 不是背光 PWM 频闪
- 换像素时钟后闪屏消失 → 定位到链路时序余量

## 走过的死路（别重复踩）

**想凑精确 50Hz 而缩短水平消隐 → 面板直接黑屏（有背光、无图像）。**

试过 `htotal 2200 → 2112`（`hfront 88→32`、`hback 148→116`），算术上 `118.8MHz ÷ (2112×1125) = 50.0000` 完全正确，但面板不接受这段水平消隐，启动后整屏黑。

结论：**水平时序不能改**。要整数刷新率只能"提像素时钟 + 加垂直消隐"。

另一个已证伪的方向：

- 原厂 148.5625 MHz（60Hz）会闪，所以精确 60Hz 不可行
- 118.8 MHz 下想凑 50Hz 必须改 htotal，而 htotal 不能动

## 注意事项

- **升级 `linux-dtb-edge-rockchip64` 会覆盖 dtb**，补丁失效、闪屏复现。用 `--hold` 锁住包，或升级后重跑脚本（幂等）。
- 需要 `fdtget` / `fdtput`（`apt install device-tree-compiler`）。Armbian 这套镜像自带。
- 脚本会改动 `/boot/dtb/.../rk3588-really.dtb`，请自行保留备份并理解风险。
- 补丁只改刷新率相关参数，不动内核、不动驱动、不动 bootloader。

## 附带发现（与本补丁无关）

同一台机器上另外两个问题，供参考，本仓库不处理：

- 背光 PWM 只有 **1 kHz**（`febf0000.pwm`，周期 1 ms），亮度与占空比是反相关系。1 kHz 偏低，接摄像机拍摄时可能出现滚动横纹，建议 20 kHz 以上。
- 该机型**没有 RTC**（`RTC time: n/a`），系统时间会来回跳，排查问题时时间戳不可信。
